# Estuda-AI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Site de estudos em que a IA gera um plano com flashcards a partir de um tema e o FSRS agenda as revisões.

**Architecture:** Next.js (App Router) no Vercel. O cliente fala direto com o Supabase (Auth + Postgres protegido por RLS) para CRUD; revisões são gravadas pela função `record_review` via RPC. A geração por IA passa pela rota `POST /api/generate`, que usa a chave do próprio usuário (header) e o SDK da Anthropic com saída estruturada.

**Tech Stack:** Next.js 16, React, TypeScript (strict), Tailwind CSS, `@supabase/supabase-js` + `@supabase/ssr`, `ts-fsrs` 5.x, `@anthropic-ai/sdk` 1.x, `zod` 4.x, `react-markdown` + `rehype-sanitize` + `rehype-highlight`, Vitest + Testing Library, Playwright, Supabase CLI (pgTAP), GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-10-21-estuda-ai-design.md`

## Global Constraints

- Todo texto de interface em português do Brasil.
- Modelo de IA: `claude-opus-5-5`, com `thinking: {type: "adaptive"}`, `output_config.effort: "medium"` e `output_config.format` (JSON Schema). Nunca usar `budget_tokens`, prefill nem `tool_choice` forçado.
- A chave da Anthropic vive só em `localStorage` (chave `estuda-ai:anthropic-key`), vai no header `x-anthropic-key` e nunca é gravada, logada ou repassada.
- Limites: tema 3–200 caracteres, contexto até 1000, plano com 4–8 etapas, 5–10 cartões por etapa.
- Níveis: `iniciante`, `intermediario`, `avancado`.
- Novos cartões por dia padrão 20; retenção desejada padrão 0.9.
- Toda tabela tem `user_id` e RLS com `user_id = auth.uid()`.
- Notas FSRS: 1 Errei, 2 Difícil, 3 Bom, 4 Fácil.
- Markdown sempre renderizado com `rehype-sanitize`.

## Review Focus

1. **Fuso horário na fila do dia:** "vence hoje" deve usar o fim do dia local do usuário, não UTC; um cartão com `due` às 23h locais entra na fila de hoje. Teste em Task 3.
2. **Limite de cartões novos já parcialmente gasto:** se o usuário já estudou 15 novos hoje, a fila traz só mais 5. Teste em Task 3.
3. **Resposta da IA com etapa fora dos limites** (3 cartões ou 12 cartões): validação rejeita e dispara a nova tentativa, sem salvar nada parcial. Teste em Task 4.
4. **Duplo clique na avaliação:** apertar "Bom" duas vezes rápido não pode gravar duas revisões. Teste em Task 10.
5. **Sair da prévia sem salvar:** recarregar `/novo` com prévia aberta não pode criar plano no banco; o rascunho fica só no estado do cliente. Teste em Task 8.

**Interfaces:**
- Produces:
  - `generateRequestSchema` (zod): `{ mode: 'plan' | 'step' | 'ping', topic, level, context?, step?: { title, goal } }` com os limites globais.
  - `planSchema` (zod) → `type GeneratedPlan = { steps: { title: string; goal: string; cards: { front: string; back: string }[] }[] }`; `stepSchema` → `GeneratedStep`.
